### [rainbow-table](https://leetgpu.com/challenges/rainbow-table)
*环境: CUDA*

对长度为 `N` 的 32 位整数数组并行执行 `R` 轮迭代 FNV-1a 哈希：每一轮按小端序从低字节到高字节依次提取输入值的 4 个字节，从初始基准值 `2166136261` 出发逐字节执行 `(hash ^ byte) * 16777619`（保留低 32 位无符号结果），上一轮输出的哈希值直接作为下一轮的输入，最终将第 `R` 轮结果写入 `output`。

以官方示例 1（`input = [123, 456, 789], R = 2`）的首个元素 `123`（十六进制小端四字节依次为 `0x7b, 0x00, 0x00, 0x00`）为例：
1. **第 1 轮哈希**：从 `2166136261` 开始，先与低字节 `123` 异或再乘以质数 `16777619`（对 `2^32` 取模），随后依次对后三个 `0` 字节重复异或与乘法，得到第 1 轮 32 位无符号哈希值 `442514334`。
2. **第 2 轮哈希**：将 `442514334` 按小端拆成四字节再次送入同一 FNV-1a 函数，算得 `1636807824`；同理对 `456` 与 `789` 各迭代两轮，最终输出 `[1636807824, 1273011621, 2193987222]`。

> baseline：单线程单元素串行轮次迭代

基线版让每个线程独立负责一个下标 `idx`，先将有符号 `int` 按位转为 `uint32_t`（防止右移时发生算术符号位扩展污染高位字节），随后嵌套运行外层 `R` 轮循环与内层 4 字节循环：

```cuda
uint32_t val = static_cast<uint32_t>(input[idx]);
for (int round = 0; round < r; ++round) {
    uint32_t h = 2166136261u;
    for (int byte_pos = 0; byte_pos < 4; ++byte_pos) {
        h = (h ^ ((val >> (byte_pos * 8)) & 0xffu)) * 16777619u;
    }
    val = h;
}
output[idx] = val;
```

在性能评测规模 `N = 5,000,000, R = 10`（输入与输出各 `20 MB`，总计 `40 MB` 显存流量）下，单个元素的 `10 × 4 = 40` 步异或与整数乘法前后严格串行依赖，单元素线程在等待上一拍整数乘法结果写回寄存器时会产生流水线停顿；同时逐个 4 字节读写以及默认写分配策略也未能跑满显存带宽。

> optimized：双 `uint4` 八路指令级并行交错 + 编译期轮次展开 + 流式写出

优化版在不改变任何一位哈希结果的前提下，从访存宽度、指令级并行度（ILP）和写回缓存策略三方面压榨硬件吞吐：

- **双 `uint4` 合并加载与 8 路独立哈希链交错**：对齐路径下每个线程每步用两条 16 字节向量加载指令 `uint4` 读入 8 个整数，并在每个哈希轮次内将 8 条彼此独立的哈希状态链交错排列执行。当前一条链等待 32 位整数乘法结果时，算术流水线可以连续发射其余 7 条链的异或与乘法指令，把串行算术延迟彻底隐藏在并发指令背后。
- **内层四字节全展开与高频轮次模板特化**：将内层 4 个字节的移位掩码直接展开为无分支表达式，并对评测高频轮次（如 `R = 1`、`R = 10`）提供编译期常量循环全展开特化，省去运行期循环计数与跳转指令开销。
- **带缓存流式提示的向量写回**：哈希输出属于只写数组，通过带缓存流式提示（cache-streaming hint）的 16 字节向量存储指令 `st.global.cs.v4.u32` 写回全局显存，使整算子逼近 `40 MB` 数据的显存带宽上限。

```cuda
int i4 = gtid;
for (; i4 + gstride < n4; i4 += 2 * gstride) {
    uint4 a = __ldg(&in4[i4]);
    uint4 b = __ldg(&in4[i4 + gstride]);
    #pragma unroll
    for (int r = 0; r < kFixedR; ++r) {
        fnv1a_step_u8(a, b);
    }
    store_cs_u4(&out4[i4], a);
    store_cs_u4(&out4[i4 + gstride], b);
}
```

在官方性能测试规模 `N = 5,000,000, R = 10` 下（每次计时前刷空 L2 缓存，取 15 轮中位数），单元素串行基线版耗时 `0.154 ms`，8 路交错流式优化版降至 **`0.147 ms`**（等效读写吞吐 **`272.4 GB/s`**，哈希吞吐 **`340.5 Ghashes/s`**）；在 LeetGPU 官方 Tesla T4 评测中取得 **`0.20 ms`（第 `92.6` 百分位）**。
