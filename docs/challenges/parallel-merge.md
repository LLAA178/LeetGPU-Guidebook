### [parallel-merge](https://leetgpu.com/challenges/parallel-merge)
*环境: CUDA*

给定两个已按非递减顺序排好序的 32 位浮点数组 `A`（长度 `M`）和 `B`（长度 `N`），将它们合并为单个长度为 `M + N` 的非递减有序数组 `C`。

拿官方样例 `A = [1, 3, 5, 7]`（`M = 4`）、`B = [2, 4, 6, 8]`（`N = 4`）走一遍：归并后的 `C` 共 8 个元素。若想让两个工人互不等待地并行写出前半段 `C[0..3]` 和后半段 `C[4..7]`，只需沿反对角线 `i + j = 4` 做协同排名（co-rank，即对给定的输出前缀长度 `k`，唯一确定该前缀由 `A` 的前 `i` 个元素与 `B` 的前 `j = k - i` 个元素组成）：二分检查发现 `i = 2, j = 2` 时满足 `A[1] = 3 <= B[2] = 6` 且 `B[1] = 4 < A[2] = 5`，于是 `A` 切分为 `[1, 3] | [5, 7]`、`B` 切分为 `[2, 4] | [6, 8]`。工人 0 独立归并 `[1, 3]` 与 `[2, 4]` 写出 `[1, 2, 3, 4]`，工人 1 独立归并 `[5, 7]` 与 `[6, 8]` 写出 `[5, 6, 7, 8]`；遇到相等元素时统一约定 `A[i] <= B[j]` 优先取 `A`，保证所有切分边界严格不重不漏。

> baseline

每个线程直接对应一个输出下标 `k`，在全局显存的 `A` 和 `B` 上沿 `i + j = k` 二分查找协同排名 `(i, k - i)`，比较 `A[i]` 与 `B[k - i]` 后直接写回 `C[k]`。

```cuda
int low = (diag > N) ? (diag - N) : 0, high = (diag < M) ? diag : M;
while (low < high) {
  int mid = low + ((high - low) >> 1);
  if (A[mid] <= B[diag - 1 - mid]) low = mid + 1;
  else                             high = mid;
}
// 得到 i = low, j = k - i，按 (j >= N || (i < M && A[i] <= B[j])) 选出 C[k]
```

> optimized：归并路径两级分块 + 字节对齐 `float4` 加载 + 寄存器缓存归并与流式写出

官方性能测试规模为 `M = 25,000,000`、`N = 25,000,000`，共需读取 `200 MB` 并写出 `200 MB`（总流量 `400 MB`）。朴素实现每个输出元素都要在全局显存上做约 25 次离散二分读取，显存带宽被随机探测耗尽。优化版在**零额外全局显存、单次 kernel 启动**的前提下将全流程打造成纯顺序流式访存：

- **双线程束并行块级协同排名**：每个 256 线程块负责 `4,096` 个输出元素（每线程 `16` 个元素），仅让 0 号线程与 32 号线程分别在两个独立线程束（warp，锁步执行的 32 个线程）内同时做一次全局二分查找，算出本块在 `A` 和 `B` 中对应的精确切片 `[a0, a1)` 与 `[b0, b1)`，把全局二分查找次数直接削减两千倍；同时复用分块缓冲区传递这两个整数，使每块静态共享内存（shared memory，线程块内高速片上内存）精确控制在 `16.0 KiB`，在 Tesla T4（每流式多处理器 `48 KiB` 上限）上刚好驻留 3 个线程块。
- **运行时 16 字节对齐剥离 `float4` 加载与寄存器缓存归并**：块级切分起点 `a0`、`b0` 往往并非 4 的倍数；先根据 `A + a0` 与 `B + b0` 的实时字节地址剥离 `0..3` 个首尾元素，主体全部走 128 位 `float4` `__ldg` 向量加载灌入共享内存。随后每个线程在共享内存里做一次仅约 12 步的短二分定位各自起点 `(a_idx, b_idx)`，并在 16 步串行归并循环中把两路当前值 `(va, vb)` 缓存在寄存器中——每产出一个元素只需从共享内存补读被消耗的那一路，将片上读取指令减半，且显式维护下标边界以正确处理正负无穷与重复值。
- **共享内存连续重排 + 128 位流式写出 `st.global.cs.v4.f32`**：若各线程直接把 16 个结果写往 `C[c0 + tid * 16 .. +15]` 会造成严重的跨步散乱写；先将每线程的 4 组 `float4` 写回共享内存排成连续有序序列，再由全块线程以步长 1 发起 128 位 `st.global.cs.v4.f32` 流式全局写出，防止 `200 MB` 纯输出数据冲刷二级缓存中供相邻线程块二分查找复用的 `A`、`B` 高层枢轴元素。

```cuda
// 寄存器缓存 (va, vb)：每步归并仅补读刚被取走的那一路，共享内存读指令减半
#pragma unroll
for (int item = 0; item < kItems; ++item) {
  const bool take_a = (b_idx >= lb) || ((a_idx < la) && (va <= vb));
  out[item] = take_a ? va : vb;
  if (take_a) { ++a_idx; if (item + 1 < kItems && a_idx < la) va = s_a[a_idx]; }
  else        { ++b_idx; if (item + 1 < kItems && b_idx < lb) vb = s_b[b_idx]; }
}
// 经 s_buf4 连续重排后，按步长 1 发射 st.global.cs.v4.f32 流式 128 位写出
```

把五千万次全局二分压缩为片上寄存器级顺序归并、并让读写两端同时跑满 128 位合并传输后，并行归并吞吐直接逼近显存物理带宽极限。在官方性能测试规模 `M = 25,000,000, N = 25,000,000` 下（每次计时前刷空二级缓存，取 15 轮中位数），本地 Tesla T4 实测中位耗时从基线的 `13.82 ms` 降至 **`1.72 ms`**（提速 **`8.02x`**，有效显存带宽达 **`232.2 GB/s`**）。
