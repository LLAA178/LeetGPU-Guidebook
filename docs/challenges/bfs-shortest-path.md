### [bfs-shortest-path](https://leetgpu.com/challenges/bfs-shortest-path)
*环境: CUDA*

给定尺寸为 `rows × cols` 的二维网格 `grid`（`0` 表示可通行空地，`1` 表示障碍物）以及起点 `(start_row, start_col)` 和终点 `(end_row, end_col)`，只允许上下左右四连通移动，求从起点到终点的最少移动步数并写入 `result[0]`（起点与终点重合时返回 `0`，不可达时返回 `-1`）。

用官方 `4 × 4` 例子 `grid = [[0,0,0,0], [1,1,0,1], [0,0,0,0], [0,1,1,0]]`、起点 `(0, 0)`、终点 `(3, 3)` 走一遍：
1. **逐层波前扩展**：第 0 层包含 `(0, 0)`；第 1 层向右推到 `(0, 1)`；第 2 层到 `(0, 2)`；第 3 层向下穿过唯一缺口 `(1, 2)`（同时向右到 `(0, 3)`）；第 4 层抵达 `(2, 2)`；第 5 层展开到 `(2, 1)` 与 `(2, 3)`；第 6 层从 `(2, 3)` 向下抵达终点 `(3, 3)`。
2. **输出最短步数**：首次触达终点所在的层号 `6` 即为全局最短路径长度。

> baseline

基线版采用标准的单向逐层前沿广度优先搜索（BFS）：用三个位图分别记录已访问集合 `vis`、当前层前沿 `cur` 与下一层前沿 `nxt`，每推进一层扫描当前前沿中的活跃格子，用原子按位或操作将四邻域中未访问的空地加入下一层前沿，直到命中终点或前沿耗尽：

```cuda
// 取出当前层前沿位字中的格子，检查上下左右四个邻居并原子标记下一层前沿
if ((g_base_vis[nw] & nbit) == 0u && grid[nidx] == 0) {
    const uint32_t old_v = atomicOr(&g_base_vis[nw], nbit);
    if ((old_v & nbit) == 0u) {
        if (nidx == end_idx) local_found = 1;
        atomicOr(&g_base_nxt[nw], nbit);
    }
}
```

> optimized：全线程束位棋盘四邻域膨胀 + 较小跨度优先双向波前 + 动态活跃行区间裁剪

看官方约束 `1 <= rows, cols <= 1,000`（计时规模 `500 × 500`）：
- **关键硬件映射**：`cols <= 1,000` 意味着每一行最多只需 `ceil(1000 / 32) = 32` 个 32 位无符号整数（`uint32_t`），**整行恰好装进 1 个线程束（warp，32 个线程）的单个寄存器里**！`500 × 500` 整张网格压成 1 比特/格的位棋盘（bitboard）后仅占 **`31.25 KiB`**，连片上缓存都装不满。
- **单向队列搜索的三重浪费**：逐格原子入队存在严重分支发散与原子冲突；多核函数逐层启动在千步路径上要付出数千次启动开销；遇到终点被局部障碍包围的不可达图时，单向搜索还会把起点连通的成千上万个格子全部扫完才发现死路。

优化版将二维网格搜索彻底改造成寄存器级并行位运算与双向动态波前推进：
- **`__ballot_sync` 全流多处理器极速压位与四平面布尔化简**：预处理核函数让每个线程束合并读取一行 `grid`，单条硬件投票指令 `__ballot_sync(0xffffffffu, col < cols && grid[...] == 0)` 即可把 32 个整型格子压成 1 个 `uint32_t` 空地掩码（`500 × 500` 耗时仅数微秒）。进一步利用布尔恒等式：记 `unvis_s`、`unvis_t` 分别为正向与反向**尚未访问的空地位图**，由于新前沿 `next_f = nbr & unvis_s` 必定全落在空地上，它与反向已访问集合的交集等价于 `next_f & (~unvis_t)`，省去单独维护 `free_mask` 与两份 `visited` 位图，静态缓存总占用仅 `768 KB`。
- **单周期线程束位膨胀替代逐格分支**：在波前推进核函数内，每个线程束负责一行，上下邻居直接取相邻行同列寄存器 `f_up | f_dn`，左右邻居通过两条洗牌指令 `__shfl_up_sync` / `__shfl_down_sync` 交换跨字边界比特后与 `(f << 1) | (f >> 1)` 按位或，仅用几条无分支位指令就能同时推进一整行 `1,000` 个格子：

```cuda
// 两条线程束洗牌指令传递跨 32 位字边界的比特，单次位或完成整行 <=1024 列的左右膨胀
uint32_t from_left = __shfl_up_sync(0xffffffffu, f >> 31, 1);
if (lane == 0) from_left = 0u;
uint32_t from_right = __shfl_down_sync(0xffffffffu, f & 1u, 1);
if (lane + 1 >= W) from_right = 0u;
const uint32_t nbr = (f << 1) | from_left | (f >> 1) | (from_right << 31) | f_up | f_dn;
```

- **较小跨度优先双向波前 + 动态活跃行窗口 `[cur_lo, cur_hi]`**：同时从起点和终点向中间扩展，每步实时统计非空前沿的最小行与最大行 `[mn, mx]`，下一步只扫描 `[cur_lo - 1, cur_hi + 1]` 活跃条带，并**优先扩展当前活跃行跨度更小的一端**。在连通图上搜索半径与扫描面积双双减半；在局部受困的不可达图或九曲十八弯的蛇形迷宫上，每步仅唤醒寥寥数行；中等及以下网格（如 `<= 238 × 238`）更直接单核全片上共享内存（shared memory）直出。

在官方性能测试规模 `rows = 500, cols = 500` 下（每次计时前刷空二级缓存，取 15 轮中位数），本地 Tesla T4 逐层前沿基线耗时 `5.26 ms`（在 `25%` 障碍密度的千步可达迷宫下为 `34.93 ms`），双向位棋盘波前优化版分别降至 **`0.013 ms`**（提速 **`399.1x`**）与 **`0.015 ms`**（提速 **`2264.9x`**）。
