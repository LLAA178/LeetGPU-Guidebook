### [sorting](https://leetgpu.com/challenges/sorting)
*环境: CUDA*

将长度为 `N` 的 32 位单精度浮点数（`float`）数组原地按升序排序，最终有序结果直接写回原数组 `data`。

以官方示例 `data = [5.0, 2.0, 8.0, 1.0, 9.0, 4.0]`（`N = 6`）为例，升序排列后输出 `[1.0, 2.0, 4.0, 5.0, 8.0, 9.0]`。当输入同时包含负数与正数（如性能评测的 `[-1000.0, 1000.0]`）时，若想用线性复杂度的整数基数排序直接处理 `float`，需要先对 IEEE-754 位模式做一次保序双射变换：非负数的指数与尾数原本就随数值增大而单调递增，只需把最高位符号位从 `0` 翻转为 `1`（异或 `0x80000000`），使其落在无符号高半区；负数的绝对值越大则真值越小，将全部 32 位整体取反（异或 `0xffffffff`）即可同时把符号位置为 `0`（落在无符号低半区）并反转大小顺序。例如 `-8.0`（`0xc1000000`）取反得 `0x3effffff`，`-2.0`（`0xc0000000`）取反得 `0x3fffffff`，`+2.0`（`0x40000000`）翻符号位得 `0xc0000000`，三者作为无符号整数满足 `0x3effffff < 0x3fffffff < 0xc0000000`，排序完再做逆变换就能无损还原成原浮点数（且自然满足 `-0.0` 排在 `+0.0` 之前）。

> baseline：分块共享内存加速的双调排序

基线版将长度补齐到不小于 `N` 的最小 2 的幂（超出 `N` 的尾部位置填入最大值哨兵 `0xffffffff`），实现经典的双调排序网络（Bitonic Sort）：先把每 `1,024` 个元素装进片上共享内存（shared memory，块内高速缓存）构造初始有序子块，跨块大步长阶段在全局显存做比较交换，当步长收敛回 `512` 以内时再次在共享内存内一次排完尾部 10 层：

```cuda
const int lo = ((tid / j) * (j << 1)) + (tid & (j - 1));
const int hi = lo ^ j;
const uint32_t a = s_keys[lo];
const uint32_t b = s_keys[hi];
if ((a > b) == asc) {
    s_keys[lo] = b;
    s_keys[hi] = a;
}
```

在评测规模 `N = 1,000,000`（补齐至 `2^20 = 1,048,576`）下，双调排序的时间复杂度为 `O(N log^2 N)`，一共需要执行 `20 × 21 / 2 = 210` 层比较交换、启动 67 次核函数，大量跨块长步长比较要反复读写全局显存。

> optimized：IEEE-754 保序双射融合 + 二级缓存驻留 Onesweep 基数排序

优化版把保序位变换直接融合进单趟扫描基数排序（Onesweep）的首尾访存中，以 `O(N)` 线性复杂度在二级缓存（L2 cache）内完成原地排序：

- **零额外趟次的原地位变换融合**：全局直方图核函数用 `uint4`（单条指令读取 16 字节、4 个元素）扫一遍 `data`，在寄存器内即时完成 `bits_to_key` 变换并统计全部 4 个字节位段的 `4 × 256` 桶计数，同时把 `4 MB` 的输入预热进 Tesla T4 的 `4 MB` 二级缓存。设备端规划器自动识别并跳过字节全相同的平凡趟：对于常规 4 趟路径，第 0 趟从 `data` 读取时顺手完成 `float → key` 变换写入 `4 MB` 乒乓缓冲 `g_temp`，中间两趟在 `g_temp` 与 `data` 之间直接交换无符号键，第 3 趟写回 `data` 时顺手完成 `key → float` 逆变换，省去独立的预处理与后处理核函数；当有效趟数为奇数时由轻量收尾步把 `g_temp` 转换写回 `data`；当 `N <= 2048` 时则直接在单个线程块的 `24 KB` 共享内存里一趟排完。
- **`__match_any_sync` 束内排名与免清零纪元回看**：每个工作块（256 线程处理 `2,048` 个元素，`N = 1,000,000` 共 `489` 个块）用 `atomicAdd` 动态领取块号，在线程束（warp，32 个锁步执行的线程组）内调用硬件等值匹配指令 `__match_any_sync` 单拍算出相同桶号的线程掩码与稳定排名；随后 256 个线程并行在紧凑的 `1 MB` 64 位状态表上执行带递增轮次号（epoch）的解耦回看（Decoupled Look-back），免去每次调用间的显存清零。
- **片上分桶重排与二级缓存高速周转**：线程先将块内元素按桶序重排到片上 `s_keys[2048]`，再按连续下标合并写往目标数组。由于 `data`（`4 MB`）与 `g_temp`（`4 MB`）的活跃块高度命中二级缓存，全部 5 次核函数启动都能以远高于片外显存的带宽快速完成。

```cuda
__device__ __forceinline__ uint32_t bits_to_key(uint32_t u) {
    const uint32_t mask = (u & 0x80000000u) ? 0xffffffffu : 0x80000000u;
    return u ^ mask;
}

__device__ __forceinline__ uint32_t key_to_bits(uint32_t key) {
    const uint32_t mask = (key & 0x80000000u) ? 0x80000000u : 0xffffffffu;
    return key ^ mask;
}
```

本地 Tesla T4（CUDA 12.4）每次计时前刷空二级缓存，在官方评测规模 `N = 1,000,000` 下取 15 轮中位数：分块双调排序基线耗时 `1.135 ms`，保序映射融合 Onesweep 优化版降至 **`0.283 ms`**（提速 **`4.01x`**，吞吐达 **`3,536.7 Mfloats/s`**）。
